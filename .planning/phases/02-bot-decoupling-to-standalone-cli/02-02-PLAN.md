<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| inbound QQ message → host.runTurn | Unauthenticated QQ/text enters the agent loop. Boundary enforced by channel allowlist (decideQQAccess in src/qq/access.ts) — qq.ts must NOT add a parallel auth check. |
| gate-reply text → pauseGate.resolve | Channel reply parsed by consumeReply; spoofed text could forge a verdict. Same vector as 02-01 T-02-02 — mitigation extends here. |
| QQ account → PID lock | QQ_LOCK_FILE (channel.ts:11) prevents the SAME account from being driven by both the sidecar and `reasonix qq` simultaneously — D-10 coexistence safe by construction. |
| DeepSeek API key | Loaded via loadEndpoint/bridgeEndpointEnv; qq.ts must not print key material. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-05 | Spoofing | inbound QQ message identity | high | accept | Identity assertion stays in QQChannel + decideQQAccess (src/qq/access.ts). qq.ts trusts channel-vetted text. Do not reimplement auth at the command layer (would duplicate channel logic, violate D-07). Accept with rationale: D-07 explicitly defers access control to the channel module. |
| T-02-06 | Tampering | gate consumeReply → pauseGate.resolve | high | mitigate | The 02-01 T-02-02 mitigation (default-else = deny/cancel) carries here: consumePauseReply's parse*Choice fall-through routes unknown text to deny/cancel, AND the new object-injection GateCallbacks can only call resolve with verdicts the dispatcher chooses — there is no user-text → arbitrary-verdict path. Verify in tests/qq-channel-gate-callbacks.test.ts: assert unknown text -> deny choice. |
| T-02-07 | Repudiation | concurrent inbound from QQ | medium | accept | Reuse the channel's processedMsgIds dedup (channel.ts) + the host single-turn aborter; the command's busy/queue behavior (classifyDesktopQQIngress replication) drops redundant messages explicitly — the drop is logged via onInfo, not silent. Accept: explicit-drop > silent-rejection per CLAUDE.md log+crash principle. |
| T-02-08 | Information Disclosure | qq.ts error/log path | medium | mitigate | All qq.ts process.stderr.write calls use `t("commands.qq.*", {msg})` templates that interpolate a sanitized Error.message; the DeepSeek API key never reaches an onError/onInfo path because it's loaded inside loadEndpoint and consumed only by the DeepSeekClient ctor (verified by audit in 02-01 T-02-03). | T-02-09 | Denial of Service | signal handler not installed | low | mitigate | SIGINT/SIGTERM handlers must be installed BEFORE channel.start() so Ctrl-C always releases the PID lock — verify by reading qq.ts: `process.on("SIGINT", cleanup)` appears before `await channel.start()` (assertion `grep -n 'SIGINT' src/cli/commands/qq.ts` line < `grep -n 'channel.start'` line). Otherwise a crash mid-start leaks the lock. |
| T-02-SC | Tampering | npm installs | high | mitigate | No new npm install this plan — pure TS additions and one-line boundary edits. slopcheck gate not triggered. |
