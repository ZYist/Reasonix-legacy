<objective>
Redact plaintext secrets (DeepSeek API key, Telegram bot token, QQ appSecret, Weixin token) from bot command error output before it reaches stderr logs OR the chat channel. Closes GitHub issue #1 / deferred SEC-WR-05 (02-SECURITY.md AR-06).

Purpose: This is a P0 information-disclosure fix. Two verified leak surfaces: (A) the qq/telegram/weixin command controllers write raw `(err as Error).message` to stderr — grammy/Telegram send errors embed the bot token in the request URL; (B) `host.runTurn` mirrors the classified error to stderr AND returns it, and the command layer pushes that return value into the chat via `channel.sendResponse` — a DeepSeek-key-bearing error lands in the user's QQ/Telegram/WeChat conversation.

Output: A pure `redactSecretsInText` value-level scrubber (additive; existing `redactEventValue` untouched), a `collectBotSecrets` config-side secret collector, redaction wired at all five leak sites, and a regression test proving both a Telegram-URL-form token and a bare known key are removed from the scrubbed string.
</objective>

  <behavior>
    - Given a message containing a Telegram bot-URL token `bot123456789:AAF...` and knownSecrets `["sk-FAKEDEEPSEEKKEY..."]`, the returned string contains neither plaintext secret and shows `[redacted]` in their place.
    - Given a `Bearer <token>` substring anywhere in the text, the token is replaced (matching the spirit of the existing Bearer redaction) while surrounding text is preserved.
    - Given knownSecrets containing an empty string or a value shorter than the minimum length, no over-redaction occurs (benign text is unchanged).
    - Given a benign message with no secret and an empty knownSecrets array, the output equals the input.
    - collectBotSecrets(tmpConfigPath) returns an array that includes a configured DeepSeek apiKey, telegram botToken, qq appSecret, and weixin token, and excludes values below the minimum length.
    - redactEventValue is unchanged: an object with a `token` key still redacts its value; a top-level free-form string with key === null is still returned unchanged (regression guard on the public event path).
  </behavior>
  <action>
In `src/core/event-redaction.ts`, ADD a new exported pure function `redactSecretsInText(text: string, knownSecrets: readonly string[]): string`. Make `knownSecrets` a REQUIRED param (no default) so every call site is compile-time-forced to supply secrets. Do NOT modify, re-order, or change the signature/behavior of the existing `redactEventValue` / `redactUnknown` — this module must stay import-free (it is consumed by the event kernel `eventize.ts`).

Implementation order inside `redactSecretsInText`: (1) if `text` is falsy, return it as-is; (2) define a module-level `MIN_SECRET_LEN = 8`; (3) for each secret in `knownSecrets` where `secret.length >= MIN_SECRET_LEN`, literal-replace every occurrence using `String.prototype.replaceAll(secret, "[redacted]")` (literal replace avoids regex-escaping the secret and the min-length guard prevents an empty/short value from nuking the whole string); (4) apply a global Telegram-bot-token pattern `/bot\d{5,}:[A-Za-z0-9_-]{20,}/g` replacing the whole match with `[redacted]` (canonical grammy `api.telegram.org/bot<id>:<hash>/…` leak — caught even when the token is not in knownSecrets); (5) apply `/Bearer\s+\S+/gi` replacing with `Bearer [redacted]`; (6) return the result. Keep module header to at most two lines per the comment policy; no section banners, no version/incident narrative.

In `src/config.ts`, ADD an exported function `collectBotSecrets(path: string = defaultConfigPath()): string[]`. It gathers the known secret VALUES for these channels: DeepSeek key via `loadApiKey(path)`, Telegram token via `loadTelegramConfig(path).botToken`, QQ secret via `loadQQConfig(path).appSecret`, Weixin token via `loadWeixinConfig(path).token` (and, defensively, `loadWeixinConfig(path).accountId`). This collector is the "gather secrets" half — keep it in config.ts so the pure redactor never imports config.
