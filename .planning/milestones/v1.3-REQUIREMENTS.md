# Requirements: v1.3 Stable Release Hardening

**Defined:** 2026-07-17
**Status:** Active
**Product boundary:** DeepSeek-first; npm package 与 CLI 均统一为 `reasonix-legacy`; 强制测试环境仅 Windows + Node.js 24.15.0 + npm 11.16.0 + PowerShell。

## v1.3 Requirements

### 发布身份与版本权威

- [x] **ID-01**: 用户安装 npm package `reasonix-legacy` 后，只获得名为 `reasonix-legacy` 的 CLI bin；当前 package 不再暴露 `reasonix` 或 `dsnix` 命令。
- [x] **ID-02**: 维护者在 workspace、package graph、lockfile 和发布内容中不再看到 `packages/dsnix`、`dsnix` shim、file dependency 或相关 workspace 记录。
- [x] **ID-03**: 当前 README、帮助文本、安装示例、贡献文档和维护文档只使用 `reasonix-legacy` 命令；历史 CHANGELOG 与已归档里程碑不被重写。
- [x] **ID-04**: `reasonix-legacy --version` 输出明确的 `reasonix-legacy 1.3.0` 身份，运行时版本只从单一 package authority 派生。
- [x] **VER-01**: root package、lockfile root record、运行时版本、README、CHANGELOG、governance、SECURITY 与 v1.3 milestone 对同一 `1.3.0` / `v1.3` 关系无冲突。
- [x] **VER-02**: 自动一致性检查会在 package/bin/version/current-doc/release workflow 再次漂移或当前维护表面重新出现 `dsnix` 时失败。

### 供应链与安全合同

- [x] **SEC-01**: `undici` 与 `ws` 更新到修复已知高危漏洞的兼容版本，并由 lockfile 固定可复现的解析结果。
- [x] **SEC-02**: 在全新 `npm ci` 后，`npm audit --omit=dev` 不报告 high 或 critical 生产依赖漏洞。
- [x] **SEC-03**: `SECURITY.md` 准确声明 `reasonix-legacy` CLI/TUI、MCP/ACP 与 QQ/Telegram/Weixin channel 的支持边界，不再声称维护已删除的 dashboard/server/Tauri 表面。
- [x] **SEC-04**: 维护者完成 npm install-script provenance 审查并记录结论，不以自动放行或静默忽略替代审查。
- [x] **SEC-05**: 三个历史 raw `Error.message` command controller 风险被重新验证；若仍可把敏感错误原样写入 stderr，则在不改变正常错误语义的前提下完成脱敏并有回归测试。

### Windows 发布自动化

- [x] **WIN-01**: 强制 CI 只在 Windows 上使用 Node.js 24.15.0、npm 11.16.0 和 PowerShell 执行 install、docs、lint、typecheck、build 与完整 tests；Ubuntu/Node 22 不再是阻塞矩阵。
- [x] **WIN-02**: CI、CodeQL、CONTRIBUTING、governance 和 branch-protection 指引统一描述真实的 `v1` 默认分支与 `dev` 开发分支，不再引用不存在的 `main`。
- [x] **WIN-03**: CodeQL 对 `v1`/`dev` 的相关 push/PR 生效，并保留可由仓库管理员启用 required checks 的清晰指引；远程保护设置本身不由代码伪造。
- [x] **PUB-01**: root npm publish workflow 只发布 `reasonix-legacy`，使用明确且文档化的 `v1.3.0` 形式 tag 约定，并在 publish 前运行 Windows v1.3 release gates。
- [x] **PUB-02**: `publish-dsnix.yml` 被删除；`release-mirror.yml` 的 desktop/Tauri 假设被删除或退役，并明确稳定版是否仅以 npm package 为发布资产。

### 候选包与稳定版复评

- [x] **PKG-01**: 在当前 Windows 标准环境中，从干净依赖状态执行 `npm ci` 与 `npm run verify`，结果为 0 failed，且 slow/tokenizer/jobs 测试未被排除。
- [x] **PKG-02**: `npm pack --dry-run --json` 证明 tarball 含 CLI、types、tokenizer、README/LICENSE 与八个 grammar/runtime WASM，同时不含 `.planning`、凭据/session、dashboard、Tauri、desktop 或 `dsnix` 内容。
- [x] **PKG-03**: 维护者可在隔离临时目录安装生成的 tarball，并成功运行 `reasonix-legacy --version` 与 `reasonix-legacy --help`；`reasonix`/`dsnix` 不存在。
- [x] **REL-01**: 文档检查覆盖当前版本、package/bin identity、tag convention、security support scope 和移除表面，避免仅检查结构/链接却放过发布事实漂移。
- [x] **REL-02**: 新稳定版评估报告绑定最终候选 SHA，记录 Windows 命令、时间、退出码、audit/pack/隔离安装结果，并明确披露未运行的 live Telegram/Weixin/TTY UAT、HeadlessHost 事件渲染限制及外部 GitHub operator actions。

## Future Requirements

- **REF-01..04**: 在现有 characterization tests 保护下拆分 `App.tsx`、`config.ts`、`loop.ts` 和大型 tools。
- **CHAN-01**: 让 HeadlessHost channels 转发 reasoning/tool events；属于新功能，不与稳定版身份整改混合。
- **LIVE-01**: 使用 disposable credentials 对最终候选执行 Telegram/Weixin/TTY live UAT，并把 sanitized 记录保存在仓库外。

## Out of Scope

| Feature | Reason |
|---------|--------|
| 多模型/provider 适配 | 保持 DeepSeek-first，避免稀释 cache-first 与工具调用修复优化 |
| `dsnix` 或 `reasonix` 兼容 bin | 用户已决定直接统一为 `reasonix-legacy`，不设迁移期 |
| Ubuntu、macOS、Node 22 或其他运行时矩阵 | v1.3 强制标准仅为当前 Windows + Node 24.15.0 环境 |
| 自动 push/tag/publish 或修改 GitHub branch protection | 外部且可能不可逆，必须由维护者在候选通过后显式执行 |
| 真实 bot/model/TTY 流量作为自动测试 | 需要凭据和外部服务，按 live UAT 单独处理 |
| 批量改写历史 CHANGELOG、archive 或历史 tags | 历史证据保持不可变；一致性 guard 只约束当前维护表面 |
