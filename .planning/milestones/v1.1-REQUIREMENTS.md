# Requirements: reasonix-legacy v1.1

**Defined:** 2026-07-13
**Core Value:** 在终端里运行低成本、不中断的 DeepSeek 编程 agent；缓存优先降低 token 成本，工具调用 JSON 自修复保证 loop 不被坏输出打断。
**Milestone Goal:** 在不改变核心 agent 行为的前提下，统一项目事实源、将运行时 i18n 收缩为中英文、补齐关键用户路径保护并提高 CI 风险可见性，为后续热点模块拆分建立安全基础。

## v1.1 Requirements

### 治理决策

- [x] **GOV-01**: 维护者可以查阅一份明确的版本权威决策，说明 npm semver、GSD milestone、历史 tags 和首次 Pure CLI release 之间的关系。
- [x] **GOV-02**: 维护者可以查阅一份明确的仓库身份决策，区分当前 fork 的维护入口和 upstream attribution。
- [x] **GOV-03**: 维护者可以查阅一份明确的开发分支策略，规定 `dev` push 或受保护 PR 如何获得 CI 验证，并列出必须人工完成的 GitHub 设置。
- [x] **GOV-04**: 维护者可以查阅一份关键路径 coverage policy，定义全仓非回归基线和 TUI、command、channel 的目标，不以单一全局百分比代替风险覆盖。

### 当前事实源

- [x] **TRUTH-01**: 用户从中英文 README 和当前入口文档中看到的产品身份、版本说明、仓库链接及 CLI-only 能力与 live repository 一致。
- [x] **TRUTH-02**: AI 从 `.planning/codebase`、PROJECT 和 STATE 获取的当前架构、目录、集成和测试信息与 live source/import graph 一致。
- [x] **TRUTH-03**: 测试配置、mocks 和当前测试不再依赖已经删除的 Tauri、desktop 或 Web dashboard 模块。
- [x] **TRUTH-04**: 历史 CHANGELOG、已归档里程碑及合法的 `reasonix stats` dashboard 叙述保持完整，不被当前事实清理误删。

### 双语 i18n

- [x] **I18N-01**: 用户在运行时、语言选择器和发布包中只看到两个规范 locale：`en` 与 `zh-CN`。
- [x] **I18N-02**: 用户提供 `en-US`、`en-GB`、`zh`、`zh-Hans`、`zh-SG` 等受支持别名时，系统将其归一化为规范 locale。
- [x] **I18N-03**: 已有用户配置为 `ja`、`de`、`ru` 或其他不支持 locale 时，程序不会启动失败，而是按系统语言回退到 `zh-CN` 或 `en`，并将配置写回规范值。
- [x] **I18N-04**: 维护者修改中英文文案时，自动检查保证两种语言 key 完全一致，且类型系统不允许静默缺失 key。
- [x] **I18N-05**: 用户只会在当前 README、测试、fixtures 和发布资源中遇到中文或英文；其他语言的当前文档被移除，但历史 CHANGELOG 内容保留。

### 关键路径保护

- [x] **TEST-01**: 维护者可以通过离线特征测试验证 TUI composer 的输入、提交、取消和主要状态转换。
- [x] **TEST-02**: 维护者可以通过离线特征测试验证 TUI live output、滚动和关键可见反馈，不依赖真实 DeepSeek 服务。
- [x] **TEST-03**: 维护者可以通过测试验证 `run`、`commit` 和 MCP 等关键 CLI command 的参数传递、成功输出及失败退出行为。
- [x] **TEST-04**: 维护者可以通过测试验证 Telegram 与 Weixin channel 的启动、事件转发、错误、关闭和中断生命周期。
- [x] **TEST-05**: 默认测试无需真实网络、bot 凭据或交互式 TTY；无法自动化的 live UAT 被显式记录，而不会伪装成自动化覆盖。

### CI 与 flaky 可见性

- [x] **CI-01**: 维护者选定的活跃开发路径会自动执行 build、lint、typecheck 和测试验证。
- [x] **CI-02**: 维护者可以在 CI 结果中识别“首轮失败、重试通过”的测试，而不是只看到最终绿色结果。
- [x] **CI-03**: CI 不会为缩短执行时间而删除 tokenizer、jobs 或其他必要慢测试；任何排除项都有明确证据和记录。

## Future Requirements

### v1.2 候选：复杂度热点拆分

- **REF-01**: 在特征测试保护下拆分 `App.tsx`，一次只提取一个职责边界。
- **REF-02**: 分离 `config.ts` 的 schema/default、parse/validate、migration 和 read/write 职责。
- **REF-03**: 小步提取 `loop.ts` 中可证明的状态转换或 adapter，不改变 cache、repair、folding 或 event semantics。
- **REF-04**: 分离大型 tools 的纯解析/策略与 IO executor。

## Out of Scope

| Feature | Reason |
|---------|--------|
| 新增产品功能或重新引入 Web/Tauri UI | 本里程碑聚焦风险收敛，并延续 Pure CLI 产品方向 |
| 自动发布、移动或重写 tags | 需要独立人工授权，且超出代码仓库内治理范围 |
| 自动修改 GitHub branch protection | 属于外部 operator action，仓库文件无法独立保证 |
| 删除 QQ、Telegram 或 Weixin channel | live UAT 缺少凭据不等于功能无效 |
| v1.1 内实际拆分 `App.tsx`、`config.ts`、`loop.ts` 或大型 tools | 先建立特征测试和风险基础设施，留作 v1.2 候选 |
| 仅为提高 coverage 编写无断言测试或逐行 mock 实现 | 不能提供用户可观察行为保护，反而锁死实现细节 |
| 批量改写历史 CHANGELOG 或归档里程碑 | 历史记录不是当前功能声明，应保持完整 |
